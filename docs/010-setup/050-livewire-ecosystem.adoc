== 2. Livewire 4

=== 2.1. Package Overview

**Package Name**: `livewire/livewire`
**Version**: `^4.0`
**Purpose**: Server-side rendered interactive components for Laravel
**Architectural Role**: Frontend interactivity layer providing reactive UI without writing JavaScript

**What is Livewire?**
Livewire is a full-stack framework for building dynamic, reactive user interfaces in Laravel applications without writing custom JavaScript. It allows you to create interactive components using only PHP and Blade templates.

**How Livewire Works:**
1. You create a PHP class (component) that holds the component's state and logic
2. You create a Blade view that displays the UI
3. When users interact with the component (click buttons, fill forms, etc.), Livewire sends AJAX requests to the server
4. The server processes the request, updates the state, and returns the updated HTML
5. Livewire automatically updates the page without a full refresh

**Why use Livewire?**
* **No JavaScript Required**: Build interactive UIs using only PHP and Blade
* **Familiar Syntax**: Uses Laravel's existing patterns (controllers, models, Blade)
* **Real-time Updates**: Components update automatically when state changes
* **Easy Learning Curve**: If you know Laravel, you can learn Livewire quickly
* **Full Laravel Integration**: Access all Laravel features (Eloquent, validation, authentication, etc.)

**Real-World Examples:**
* **Forms**: Create dynamic forms with validation that updates in real-time
* **Counters**: Build counters, toggles, and interactive buttons
* **Search**: Implement live search that filters results as you type
* **Dashboards**: Create dashboards that update without page refreshes
* **File Uploads**: Upload files with progress bars
* **Data Tables**: Build sortable, filterable data tables

=== 2.2. Key Features

* **Server-Side Rendered Components**: Components render on the server, reducing JavaScript complexity
* **Real-Time Updates**: UI updates automatically without page refresh
* **Two-Way Data Binding**: Changes in the UI automatically update component properties and vice versa
* **File Uploads**: Upload files with progress tracking
* **Polling**: Automatically refresh component data at intervals
* **Lazy Loading**: Load components only when they're visible
* **Event System**: Components can communicate with each other via events
* **Validation**: Built-in form validation with error display
* **Lifecycle Hooks**: Methods that run at specific points in a component's lifecycle

=== 2.3. Principles and Patterns

* **Server-Side Rendering**: Components render on the server, reducing JavaScript complexity
* **Reactive Pattern**: Components automatically update when state changes
* **Component-Based Architecture**: Reusable UI components
* **Event-Driven Communication**: Components communicate via events

**Source**: https://livewire.laravel.com/docs/quickstart[Livewire Quickstart] | https://livewire.laravel.com/docs/components[Livewire Components Documentation]

=== 2.6. Example Component

Let's create a simple counter component to understand how Livewire works. This component will have increment and decrement buttons.

==== 2.6.1. Create the Component

Use the artisan command to create a Livewire component:

[source,bash]
----
php artisan make:livewire Counter
----

**What this command does:**
* Creates the component class at `app/Livewire/Counter.php`
* Creates the component view at `resources/views/livewire/counter.blade.php`

==== 2.6.2. Component Class

The component class (`app/Livewire/Counter.php`) contains the component's state and logic:

[source,php]
----
<?php

declare(strict_types=1);

namespace App\Livewire;

use Livewire\Component;

class Counter extends Component
{
    // Public properties are automatically available in the view
    // Changes to these properties trigger UI updates
    public int $count = 0;

    // Methods that handle user actions
    // Called when user clicks the increment button
    public function increment(): void
    {
        $this->count++; // Increase count by 1
    }

    // Called when user clicks the decrement button
    public function decrement(): void
    {
        $this->count--; // Decrease count by 1
    }

    // Required method that returns the view
    public function render(): \Illuminate\Contracts\View\View
    {
        return view('livewire.counter');
    }
}
----

**Understanding the Component Class:**
* **`public int $count = 0`**: This is a public property that holds the counter's value. Public properties are automatically available in the Blade view and can be bound to form inputs.
* **`increment()` and `decrement()`**: These are methods that handle user actions. When a user clicks a button in the view, these methods are called.
* **`render()`**: This method returns the Blade view that displays the component's UI.

==== 2.6.3. Component View

The component view (`resources/views/livewire/counter.blade.php`) displays the UI:

[source,blade]
----
<div>
    <h1>Count: {{ $count }}</h1>

    <button wire:click="increment">+</button>
    <button wire:click="decrement">-</button>
</div>
----

**Understanding the View:**
* **`{{ $count }}`**: Displays the current count value. This is automatically updated when `$count` changes.
* **`wire:click="increment"`**: This is a Livewire directive that calls the `increment()` method when the button is clicked. No JavaScript needed!
* **`wire:click="decrement"`**: Similarly, this calls the `decrement()` method.

==== 2.6.4. Using the Component

To use the component in a Blade template, use the `@livewire` directive:

[source,blade]
----
<!DOCTYPE html>
<html>
<head>
    <title>Counter Example</title>
    @livewireStyles
</head>
<body>
    <h1>My Counter Component</h1>

    @livewire('counter')

    @livewireScripts
</body>
</html>
----

**Important Notes:**
* **`@livewireStyles`**: Includes Livewire's CSS (required)
* **`@livewire('counter')`**: Renders the Counter component
* **`@livewireScripts`**: Includes Livewire's JavaScript (required)

==== 2.6.5. How It Works

When a user interacts with the component:

1. **User clicks the "+" button**
2. **Livewire sends an AJAX request** to the server with the action "increment"
3. **Server calls the `increment()` method**, which increases `$count`
4. **Server renders the updated view** with the new count value
5. **Livewire updates only the changed parts** of the page (the count display)
6. **No page refresh** - the update happens seamlessly!

**What's Special:**
* No JavaScript code needed - Livewire handles all the AJAX
* No API endpoints needed - Livewire handles routing automatically
* The component state is maintained on the server
* Updates happen in real-time without page refreshes

=== 3.6. Example Volt Component

Create a Volt component using the Folio artisan command:

[source,bash]
----
php artisan folio:page counter
----

This creates a page at `resources/views/pages/counter.blade.php`:

[source,php]
----
<?php

use Livewire\Volt\Component;

new class extends Component
{
    public int $count = 0;

    public function increment(): void
    {
        $this->count++;
    }

    public function decrement(): void
    {
        $this->count--;
    }
};

?>

<div>
    <h1>{{ $count }}</h1>
    <button wire:click="increment">+</button>
    <button wire:click="decrement">-</button>
</div>
----

=== 3.7. Volt Routing

Volt components can be routed directly:

[source,php]
----
// In routes/web.php
use Livewire\Volt\Volt;

Volt::route('settings/profile', 'settings.profile')
    ->name('profile.edit');
----

=== 5.6. Authentication Configuration

Flux Pro requires authentication. Configure credentials using environment variables:

. Create `auth.json` file (gitignored):
[source,bash]
----
touch auth.json
echo "auth.json" >> .gitignore
----

. Add credentials to `auth.json`:
[source,json]
----
{
    "http-basic": {
        "composer.fluxui.dev": {
            "username": "${FLUX_PRO_USERNAME}",
            "password": "${FLUX_PRO_PASSWORD}"
        }
    }
}
----

. Set environment variables in `.env`:
[source,env]
----
FLUX_PRO_USERNAME=your-username
FLUX_PRO_PASSWORD=your-password
----

NOTE: The `auth.json` file should be gitignored. Store credentials securely in environment variables.

== 8. Troubleshooting

=== 8.1. Issue: Components Not Updating

**Symptom**: Changes to components not reflected in browser

**Solution**:
[source,bash]
----
# Clear Livewire cache
php artisan livewire:discover

# Clear application cache
php artisan cache:clear
----

=== 8.2. Issue: Volt Components Not Routing

**Symptom**: Volt routes return 404

**Solution**: Verify mount points in `VoltServiceProvider`:

[source,php]
----
Volt::mount([
    resource_path('views/livewire'),
    resource_path('views/pages'),
]);
----
